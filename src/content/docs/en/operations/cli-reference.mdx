> **Applicable version: technical preview.** Commands that manipulate network interfaces and policy routing tables require `root` or `CAP_NET_ADMIN` privileges.

`frp-tun` provides a command-line interface covering static configuration validation, identity management, daemon operations, runtime queries, and resource cleanup.

---

## 1. Syntax

```bash
frp-tun <command> [options]
```

### Global Options

- `-h`, `--help`, `help`: Print general usage help or help for a specific subcommand.
- `-v`, `--version`, `version`: Display build version information.

### Default Control Socket Path

`frp-tun` daemon and client commands communicate over a local UNIX Domain Socket by default:
- **Default Socket Path**: `/var/run/frp-tun.sock` (equivalent to `/run/frp-tun.sock` on modern systemd Linux distributions);
- **Access Control**: Created with restricted permissions by the daemon process; client commands require appropriate read/write privileges;
- **Flag Override**: All commands that interact with the daemon accept `--socket <path>` to specify a custom control socket path.

## 2. Subcommands

### 2.1 check (Configuration Preflight)

Parses the configuration file and verifies local policy routing tables for resource conflicts. This is a **read-only check** without side effects on the network stack.

```bash
frp-tun check [-c /path/to/config.toml]
```

- `-c`, `--config <path>`: Path to configuration file (default: `/etc/frp-tun/config.toml`).

---

### 2.2 init (Site Identity Initialization)

Initializes local identity storage, generating a new private key or importing from existing key material.

```bash
frp-tun init [--dir /etc/frp-tun] [--import /path/to/private.key]
```

- `--dir <path>`: Identity directory (default: `/etc/frp-tun`).
- `--import <file>`: Optional path to an existing private key file to import.

---

### 2.3 export (Export Peer Declaration)

Generates a JSON declaration containing public identity parameters (site ID, public key, allowed prefixes) for offline exchange.

```bash
frp-tun export [-c /path/to/config.toml]
```

- `-c`, `--config <path>`: Path to configuration file (default: `/etc/frp-tun/config.toml`).

> **Security Guarantee**: `export` strictly excludes private keys and only includes public routing and identity data.

---

### 2.4 import (Verified Peer Import)

Imports a peer declaration file while verifying its public key fingerprint against an expected hash.

```bash
frp-tun import --declaration <file> --fingerprint <hash>
```

- `--declaration <file>`: **Required**, path to the peer declaration JSON file.
- `--fingerprint <hash>`: **Required**, expected SHA256 fingerprint of the peer's public key.

---

### 2.5 run (Foreground Daemon Service)

Starts the `frp-tun` gateway service. Restores journal state if necessary, sets up dual-plane routing isolation, initializes WireGuard overlay and bridge pump, and listens on the UNIX control socket.

```bash
frp-tun run [-c /path/to/config.toml] [--socket /var/run/frp-tun.sock]
```

- `-c`, `--config <path>`: Path to configuration file (default: `/etc/frp-tun/config.toml`).
- `--socket <path>`: UNIX domain control socket path (default: `/var/run/frp-tun.sock`).

**v0.5.6 startup source**:

- When `journal.json` in the state directory (default `/etc/frp-tun/journal.json`) says the service should be enabled and the config digest matches, `run` restores that committed configuration instead of a config file edited later;
- A missing, unparsable, or different config file does not replace the journal. Startup logs `config file ignored` and continues from the journal;
- A missing journal file is what activates from the config file given with `-c`;
- A corrupt journal, digest mismatch, inconsistent enabled state, or missing verifiable config makes the process exit 4. It does not fall back to the config file.

---

### 2.6 status (Instance Status Query)

Connects to the control socket of a running instance and retrieves real-time operating metrics in structured JSON format (carrier transport mode, peer round-trip latencies, interface counters, and packet loss stats). In v0.5.3+, the status payload and peer entries expose the active `DialRole` (`"dialer"` or `"acceptor"`), and runtime logs include a `, dial=` tag for end-to-end link observability.

```bash
frp-tun status [--socket /var/run/frp-tun.sock]
```

- `--socket <path>`: Path to control socket (default: `/var/run/frp-tun.sock`).

---

### 2.7 doctor (Dual-Mode Environment & Online Link Diagnostics)

`frp-tun v0.5.5` introduces a dual-mode diagnostic engine in `doctor`:

- **Online Panoramic Inspection**: When the daemon is active, `doctor` communicates via the UNIX domain control socket to retrieve live IPC telemetry, including active carrier path, connection role (`DialRole`), transport protocol, session identifier, current & smoothed RTT, loss rates, standby carrier health, traffic statistics, and peer connection snapshots;
- **Offline Preflight Inspection**: If the socket is unreachable or the service is stopped, `doctor` automatically falls back to offline environment verification, validating configuration syntax, site identity private key readiness, `/dev/net/tun` device availability, and IPv4 forwarding authorization;
- **Firewall & TCP MSS Clamping Verification**: Under automatic mode, verifies the presence of `nft` in `PATH` and confirms bidirectional TCP MSS Clamping insertion for outbound tunnel interfaces; under `manual` mode, checks `/etc/config/firewall` zone `mtu_fix` compliance to prevent MTU blackholes.

```bash
frp-tun doctor [-c /path/to/config.toml] [--socket /var/run/frp-tun.sock]
```

- `-c`, `--config <path>`: Path to configuration file (default: `/etc/frp-tun/config.toml`).
- `--socket <path>`: Path to control socket (default: `/var/run/frp-tun.sock`).

**Online Mode Output Example**:
```text

[OK] active carrier: direct-quic (role=dialer, transport=quic, session=sess-01)
[OK] active QoS: rtt=18ms (smoothed=19ms), loss=0.0% (pongs=10/10)
[OK] standby carrier: direct-quic-v6 (healthy=true, fails=0)
[INFO] recovery snapshot: IPv4 available=true, IPv6 available=true, peer gen=3 (2 peer candidates)
[OK] traffic stats: tx=12.4 MiB (8420 pkts), rx=18.6 MiB (12050 pkts)

[OK] /dev/net/tun available
[OK] IPv4 forwarding authorized in config

```

**Offline Mode Output Example**:
```text

[OFFLINE] daemon not reachable via socket; operating in offline environment check mode
```

### 2.8 apply (Hot Configuration Reload)

Submits a new configuration to the running daemon. Fields that can change incrementally do not rebuild the runtime; a change that cannot be applied incrementally stops the old runtime first. Starting with `v0.5.6`, a failure during the commit rolls back to the previous generation instead of leaving a partial result.

```bash
frp-tun apply [-c /path/to/new_config.toml] [--socket /var/run/frp-tun.sock]
```

- `-c`, `--config <path>`: Path to new configuration file (default: `/etc/frp-tun/config.toml`).
- `--socket <path>`: Path to control socket (default: `/var/run/frp-tun.sock`).

**v0.5.6 rollback**:

- When a previous generation exists, a failure while arming isolation, setting forwarding, starting the runtime, or writing the journal rolls back within 30 seconds. Isolation is restored before the previous runtime is rebuilt, and the original error is still returned. The journal updates only after `apply` commits, and previously recorded retired IPv6 prefixes are kept;
- If rollback itself fails or times out, the service is marked inactive. Later `apply` calls fail with `restart required` until the process is restarted;
- Disconnecting the client cancels that `apply`. Rollback uses an independent 30-second budget and is not cancelled with the client. The control socket allows 90 seconds for `apply` and bounds the operation to 60 seconds; `down` stays at 60 seconds;
- Validation failures, and attempts to change the site identifier, are rejected before the system is modified and do not start a rollback.

### 2.9 down (Stop and Teardown Resources)

Gracefully stops the daemon and removes all owned network interfaces, policy routing rules, and blackhole filters.

```bash
frp-tun down [-c /path/to/config.toml] [--socket /var/run/frp-tun.sock]
```

- `-c`, `--config <path>`: Path to configuration file (default: `/etc/frp-tun/config.toml`).
- `--socket <path>`: Path to control socket (default: `/var/run/frp-tun.sock`).

`down` writes a stopped journal, but on `v0.5.6` that record has no site identifier. The next `run` refuses it and reports `journal missing explicit stopped state`. After owned network resources are confirmed cleaned, delete `journal.json` in the state directory so the next `run` activates from the config file. Do not delete that file while the service should keep its committed configuration.

---

### 2.10 forget-prefix (Retire IPv6 Prefix)

Unregisters a retired IPv6 prefix from persistent blackhole protection.

```bash
frp-tun forget-prefix --prefix <cidr> [--socket /var/run/frp-tun.sock]
```

- `--prefix <cidr>`: **Required**, retired IPv6 CIDR prefix (e.g. `2001:db8:1::/64`).
- `--socket <path>`: Path to control socket (default: `/var/run/frp-tun.sock`).

---

### 2.11 disable-ipv6 (Disable IPv6 Protection)

Signals the running daemon to disable IPv6 operations and clear related route rules.

```bash
frp-tun disable-ipv6 [--socket /var/run/frp-tun.sock]
```

- `--socket <path>`: Path to control socket (default: `/var/run/frp-tun.sock`).

## 3. Exit Codes

| Code | Category | Meaning |
| :--- | :--- | :--- |
| `0` | **Success** | Command finished successfully. |
| `2` | **Usage / Config Error** | Invalid flags or syntax errors in configuration. |
| `3` | **Prerequisite Failure** | Missing system requirements or resource conflicts detected. |
| `4` | **Runtime Failure** | Daemon startup failure, control socket communication error, or a journal that refuses recovery. |
