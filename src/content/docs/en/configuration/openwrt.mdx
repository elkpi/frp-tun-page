> **Applicable version: technical preview.** Specific OpenWrt SoC platforms, non-zero `SO_MARK` socket options, and long-term embedded router stability remain subject to ongoing evaluation.

```toml
[openwrt]
interface_alias = "frp-tun:REPLACE_WITH_SITE_ID"
config_path = "/etc/frp-tun/REPLACE_WITH_CONFIG_NAME.toml"

[wireguard]
private_key = "REPLACE_WITH_PRIVATE_KEY"
```

Prior to gateway deployment, verify that the daemon execution context retains `CAP_NET_ADMIN` and `CAP_NET_RAW` capabilities. Operators should back up current `ip rule`, custom routing tables, and nftables firewall rules. All upgrades should occur within designated maintenance windows with an independent manual rollback path prepared.

## Architecture & Binary Selection

When deploying on OpenWrt routers, obtain the precompiled binary from [Release Notes](/en/releases/v0.5.2/) matching your hardware architecture:

- **32-bit ARM routers (armv7 / armv7l)**: Obtain `frp-tun_v0.5.2_arm` (distribution also provides `frp-tun_arm` and `frp-tun_armv7` compatibility aliases, ~3.2MB UPX-compressed, suitable for common 32-bit ARMv7 routers);
- **64-bit ARM routers (arm64 / aarch64)**: Obtain `frp-tun_v0.5.2_arm64`;
- **MIPS / MIPSLE routers**: Obtain `frp-tun_v0.5.2_mips-softfloat` or `frp-tun_v0.5.2_mipsle-softfloat`;
- **x86_64 soft routers**: Obtain `frp-tun_v0.5.2_amd64`.
