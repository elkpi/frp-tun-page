## Summary

`frp-tun v0.5.4` delivers a vital stability and recovery mechanism enhancement. This release addresses and eliminates the recovery event storm and busy-loop defect when nodes discover zero direct candidates (e.g., absent STUN targets or restricted network interfaces). It introduces network epoch-aware exponential backoff locking and significantly cleanses operational log output.

### Key Improvements

1. **Empty Candidate Recovery Suppression & Event Storm Elimination**: Refines `refreshLocalUpdate` recovery signaling logic to only notify the supervisor when a family's preparation state (`Prepared`) actually flips or when a new candidate generation is produced, completely eliminating recovery event storm busy-loops caused by empty discovery sets;
2. **Network Epoch Backoff Guard**: Introduces network epoch tracking within `prepareFamilyLoop` for zero-candidate situations (`errNoLocalCandidates`). During exponential backoff intervals, repeat preparation triggers do not bypass the backoff timer unless the local network topology epoch actually changes, preventing discovery burst loops;
3. **Log Desensitization & Audit Optimization**: Separates temporary zero-candidate states from critical failure logging, preventing log flood during expected STUN or discovery retry periods;
4. **Rigorous Test Coverage**: Adds comprehensive end-to-end test suites in `empty_candidate_recovery_test.go` covering peering engine and supervisor behavior under zero STUN candidates, negative cache expiration, and concurrent preparation calls.

## Upgrade

1. Back up existing gateway configuration (e.g. `/etc/frp-tun/config.toml`);
2. Stop the running daemon:
   ```bash
   systemctl stop frp-tun
   ```
3. Replace the binary and set executable permissions:
   ```bash
   chmod +x frp-tun_v0.5.4_amd64
   mv frp-tun_v0.5.4_amd64 /usr/local/bin/frp-tun
   ```
4. Start the service and inspect runtime status:
   ```bash
   systemctl start frp-tun
   ```

---

## Rollback

If unexpected behavior occurs post-upgrade:
1. Stop the service: `systemctl stop frp-tun`;
2. Restore the previous verified binary to `/usr/local/bin/frp-tun`;
3. Clean up residual policy routes and interfaces (if any): `ip link delete frp-tun:0 2>/dev/null || true`;
4. Restart the previous daemon version.
