## Summary

- On-demand `frp-tun perf` sampling reports per-peer interval throughput, CPU, RSS, probe RTT, jitter and loss, fragmentation and frame counts, confirmed datagram payload limit, and more. `doctor` corrects forwarding and firewall diagnostics; `status` exposes observation errors, traffic counter generations, and datagram availability.
- The QUIC datagram send limit is no longer fixed at 1200. It probes the path and converges when the path changes or a `DatagramTooLargeError` occurs. The new `p2p.mtu_adjust` policy supports `suggest` (default), `auto`, and `off`. Suggested MTU accounts for WireGuard padding and encapsulation overhead.
- Recovery now handles owned rules and routes when the network journal is empty and recognizes connected routes on owned interfaces. Fixes cover `apply` half-close cancellation, runtime context lifetime, and canceled applies committing; gateway port mapping retries with backoff.

## Validated scope

- All five release binaries were checked against `checksums.txt`.
- In the upstream real-device A/B test on OpenWrt MT7981B at approximately 1.1 Mbps unidirectional throughput, MTU 1360 and a confirmed path payload limit of 1396 produced zero `tx_frag`, `fragment_frames`, and `reassembled` counts. Receive-side CPU increment fell approximately 29% and send-side approximately 15%. Per-packet QUIC encryption and framing remained the main send-side cost. These results apply to the tested device and conditions.
- Upstream reports regression tests for cross-process crash recovery and failed `apply` operations.

## Known limitations

- MTU recommendations, fragmentation, and CPU savings depend on hardware, network path, and load; validate them in the target environment.
- Cross-compiled assets are not a compatibility guarantee for specific hardware, sustained heavy load, nonzero `SO_MARK`, or complex NAT scenarios.
- The software has no automatic updates or availability SLA; see the [EULA](https://github.com/elkpi/frp-tun-page/blob/main/EULA.md).

## Upgrade

During a maintenance window, back up the existing configuration and binary and prepare an independent rollback path. Download the binary for the target architecture and verify its digest, then stop the service, replace the binary, and restart. Run `frp-tun doctor` to check status. When an enabled journal exists, restart restores its committed configuration; use `frp-tun apply` to change configuration. See [Upgrade & rollback](/en/operations/upgrade-rollback/).

## Rollback

Stop the service, restore the backed-up binary, restart, and check status. Reverting the binary is not the same as reverting configuration; consult the target version's release notes and journal behavior first.

## Withdrawal

For serious security or stability issues, maintainers will mark the public Release as withdrawn and publish a notice according to [SECURITY.md](https://github.com/elkpi/frp-tun-page/blob/main/SECURITY.md).
