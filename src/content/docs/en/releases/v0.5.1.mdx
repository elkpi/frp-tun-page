## Summary

`frp-tun v0.5.1` focuses on enhancing STUN/NAT traversal, weak network recovery, path-selection heuristics, and edge device probing efficiency.

### Key Improvements

1. **STUN Concurrent Racing Discovery**: DNS queries and network probes share a strict 500ms discovery budget, early-stopping as soon as 3 independent samples are collected;
2. **DNS Debounce & Cooldown**: Implements a 5-minute local DNS cache and 30-second failure cooldown to eliminate redundant resolution overhead;
3. **Cellular CGNAT Delta Prediction**: Adaptively identifies arithmetic port allocation patterns, executing 36–40 concurrent targeted predictive hole-punching attempts;
4. **Seamless Path Promotion & Fast Recovery**: Tries all approved paths concurrently upon cold boot or link disruption; prioritizes connectivity recovery before smoothly promoting preferred paths;
5. **Preferred Private Hub Debounced Fallback**: Adds a 30-second observation window and a 6-consecutive-success threshold to prevent route flapping under critical link margins;
6. **Steady-State Low Power Consumption**: Automatically lowers probe frequency once a P2P direct path stabilizes, minimizing CPU load on embedded routers.

## Upgrade

1. Back up existing gateway configuration (e.g. `/etc/frp-tun/config.toml`);
2. Stop the running daemon:
   ```bash
   systemctl stop frp-tun
   ```
3. Replace the binary and set executable permissions:
   ```bash
   chmod +x frp-tun_v0.5.1_amd64
   mv frp-tun_v0.5.1_amd64 /usr/local/bin/frp-tun
   ```
4. Start the service and inspect runtime status:
   ```bash
   systemctl start frp-tun
   ```

---

## Rollback

If unexpected behavior occurs post-upgrade:
1. Stop the service: `systemctl stop frp-tun`;
2. Restore the previous verified binary to `/usr/local/bin/frp-tun`;
3. Clean up residual policy routes and interfaces (if any): `ip link delete frp-tun:0 2>/dev/null || true`;
4. Restart the previous daemon version.
