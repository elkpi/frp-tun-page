Inspect official binary download links, SHA256 checksum manifests, and validation records across `frp-tun` public releases:

- [v0.5.17 (Current Stable Release)](/en/releases/v0.5.17/): Adds two-end tunnel MTU negotiation (lower only, hot-applied without interruption, 5-minute cooldown) and `p2p.listen_port_range` direct port drift (only after sustained failures, at most five times per 24 hours); `status` exposes effective MTU and drift counts. Negotiation requires both ends on v0.5.17; older peers fall back to unilateral `mtu_adjust`. CI and local loopback E2E pass; real-device port blocking, nonzero `SO_MARK`, and OpenWrt are not verified, and no performance gains are claimed.
- [v0.5.16](/en/releases/v0.5.16/): Adds `site.data_plane = "auto"` so each peer switches among direct QUIC, private Hubs, and public STCP; private Hubs can carry IP without WireGuard, and `frp-tun pin` pins the carrier per peer. When interoperating with fixed-mode or older peers, both ends must explicitly configure the same available `sync_port`. Local loopback E2E passes; no performance gains or real-device support are claimed.
- [v0.5.15](/en/releases/v0.5.15/): Adds `site.data_plane = "tun-quic"` for single-peer TUN over authenticated QUIC Datagrams; the default data plane remains `wg-quic`. Dynamic IPv6 prefixes synchronize over the active control stream, and the stopped-journal restart bug is fixed. Both ends must upgrade to v0.5.15 to interoperate.
- [v0.5.14](/en/releases/v0.5.14/): Userspace WireGuard hands ciphertext to the data pump through in-process per-peer queues instead of loopback UDP; kernel mode keeps UDP, and in-process device status port, logging, and shutdown behavior are fixed. The fixture comparison does not prove the default path passed the production-wiring sample threshold.
- [v0.5.13](/en/releases/v0.5.13/): Userspace WireGuard and real QUIC two-ended path attribution. Receive-direction 1400B improved CPU by 9.42%, below the 10% threshold, so production still defaults to batch receive.
- [v0.5.12](/en/releases/v0.5.12/): Fixes batched sendmmsg/recvmmsg negative-count fallback and reuses Endpoint batch-write buffers per call. Production still defaults to batch receive; receive-mode comparisons are diagnostic samples only.
- [v0.5.11](/en/releases/v0.5.11/): Batched LoopbackBind and Endpoint I/O, lazy expiry; fair benchmarks show demonstrated CPU savings only for 1400B packets, with increased heap objects per packet.
- [v0.5.10](/en/releases/v0.5.10/): Go performance optimization phase two, round one — send-buffer reuse and outbound reads into pooled buffers, plus real-QUIC benchmarks with CPU profile attribution.
- [v0.5.9](/en/releases/v0.5.9/): Go performance optimization phase one — frame IO fast paths with zero-allocation loopback transfer, event-driven active-pump management, and a controlled-load benchmark.
- [v0.5.8](/en/releases/v0.5.8/): Session-change semantics fix for the dynamic MTU observer, and a real-device CPU measurement caliber note.
- [v0.5.7](/en/releases/v0.5.7/): On-demand performance sampling, adaptive datagram sizing and tunnel MTU, and recovery and lifecycle fixes.
- [v0.5.6](/en/releases/v0.5.6/): Restore the committed configuration on restart, roll back a failed `apply`, and reject incomplete journals.
- [v0.5.5](/en/releases/v0.5.5/): Control plane signaling convergence, TCP MSS clamping, doctor dual-mode inspection, and OpenWrt UCI/LuCI stack integration.
- [v0.5.4](/en/releases/v0.5.4/): Empty candidate recovery suppression, network epoch backoff guards, and preparation log desensitization.
- [v0.5.3](/en/releases/v0.5.3/): QUIC direct connection symmetric dialing, CGNAT port block NAT fix, stream handshake deadlock prevention, and DialRole observability.
- [v0.5.2](/en/releases/v0.5.2/): WAN renumbering automatic recovery, immutable epoch fencing, single-owner data path handover, and asymmetric WireGuard keepalive.
- [v0.5.1](/en/releases/v0.5.1/): STUN concurrent racing discovery, cellular CGNAT port prediction, 32-bit ARM (armv7) support, and resilient link recovery.
