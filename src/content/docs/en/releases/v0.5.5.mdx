## Summary

`frp-tun v0.5.5` is a milestone official release focused on operational convergence, TCP transmission resilience, unified environment diagnostics, and OpenWrt ecosystem expansion. This release eliminates control-plane broadcast storms via interval throttling and fingerprint deduplication, injects automatic TCP MSS Clamping on outbound tunnel frames to eliminate MTU blackholes, upgrades `doctor` to a dual-mode online/offline diagnostic engine, removes loopback UDP deadline system-call overhead on data planes, and introduces official OpenWrt UCI configuration templates and the `luci-app-frp-tun` real-time dashboard.

### Key Improvements

1. **Control Plane Signaling Convergence**: Enforces a 10-second minimum transmission interval and fingerprint deduplication in `peerExchange`. Immediate broadcast is permitted only when local or peer candidate generations increment or when candidate topology genuinely changes, completely eliminating millisecond-level duplicate broadcast storms;
2. **Log Semantic Leveling & Desensitization**: Transitions periodic channel TTL renewal logging from high-frequency spam to aggregated periodic output, eliminating 77.4% of steady-state log noise while retaining `Info`-level audit trails for genuine set changes;
3. **Session Slot State Diagnostics**: Emits a structured snapshot `[family:state:id:age]` with a 10-second rate limiter when `candidate_open_slot_full` is encountered, enabling swift isolation of hung handshakes or zombie peer connections;
4. **Outbound Tunnel TCP MSS Clamping**: Injects bidirectional TCP MSS clamping rules into the `nftables` forwarding chain (`tcp flags syn tcp option maxseg size set rt mtu - 40`), eliminating packet fragmentation, MTU blackholes, and stalled HTTPS TLS handshakes caused by overlay encapsulation;
5. **Doctor Dual-Mode Unified Diagnostics**: Upgrades the `doctor` command to a dual-mode architecture. Running instances read real-time IPC link health, smoothed RTT, loss rates, and active/standby status over the UNIX control socket; offline mode inspects TUN device availability, cryptographic materials, and OpenWrt firewall zone `mtu_fix` compliance;
6. **Loopback Data Plane Performance Optimization**: Eliminates per-packet `SetReadDeadline` system calls in WireGuard loopback UDP processing, decreasing per-packet CPU consumption by 13.4%, boosting overall throughput by 16.1%, and reducing p50 latency by 74.2% with zero memory growth;
7. **OpenWrt Full-Stack Ecosystem Support**: Ships official `/etc/config/frp-tun` UCI templates, Procd dual-mode service synthesis (supporting both standalone TOML and dynamic UCI generation), and `luci-app-frp-tun` for real-time web UI status monitoring.

## Upgrade

1. Back up existing gateway configuration (e.g. `/etc/frp-tun/config.toml` or `/etc/config/frp-tun`);
2. Stop the running daemon:
   ```bash
   systemctl stop frp-tun
   ```
3. Replace the binary and set executable permissions:
   ```bash
   chmod +x frp-tun_v0.5.5_amd64
   mv frp-tun_v0.5.5_amd64 /usr/local/bin/frp-tun
   ```
4. Run dual-mode environment preflight checks and start the service:
   ```bash
   frp-tun doctor -c /etc/frp-tun/config.toml
   systemctl start frp-tun
   ```
5. Inspect online operational status:
   ```bash
   frp-tun doctor
   ```

---

## Rollback

If unexpected behavior occurs post-upgrade:
1. Stop the service: `systemctl stop frp-tun`;
2. Restore the previous verified binary to `/usr/local/bin/frp-tun`;
3. Clean up residual policy routes and interfaces (if any): `ip link delete frp-tun:0 2>/dev/null || true`;
4. Restart the previous daemon version.
