## Summary

`frp-tun v0.5.2` focuses on automatic perception of WAN renumbering in dynamic networking environments, steady promotion of P2P candidates, and adaptive graceful return.

### Key Improvements

1. **Netlink Address & Egress Fingerprint Observation**: Subscribes dynamically to Linux Netlink address and routing events, extracting egress interface index and default/direct route fingerprints, supporting 250ms debouncing, 30s polling fallback, and graceful degradation;
2. **Per-Family Network Epochs & Resource Isolation**: Introduces independent NetworkEpoch and lease accounting, incrementing independently across IPv4/IPv6 changes to ensure smooth handover and bounded cleanup of stale resources (max 1 retired resource per family);
3. **Immutable Epoch Fencing**: Binds asynchronous STUN probes, port mappings, and QUIC handshakes to immutable epochs, preventing cross-epoch stale results from polluting active candidate pools;
4. **Candidate Data Plane Probing & Single-Owner Handover**: Stream candidate channels use independent Nonce Ping/Pong over user data streams for bi-directional verification; Supervisor triggers tokenized single-owner handover with a 5-second receive-only grace window on old relays to eliminate packet drop;
5. **Asymmetric WireGuard Keepalive Heuristic**: Distinguishes Visitor and Proxy roles, configuring persistent keepalive exclusively on initiator endpoints to eliminate concurrent cross-handshake collisions;
6. **Cross-Version Compatibility Assurance**: Adds controlled interoperability fixtures against historical v0.5.1 nodes to guarantee seamless mixed-version cluster operation.

## Upgrade

1. Back up existing gateway configuration (e.g. `/etc/frp-tun/config.toml`);
2. Stop the running daemon:
   ```bash
   systemctl stop frp-tun
   ```
3. Replace the binary and set executable permissions:
   ```bash
   chmod +x frp-tun_v0.5.2_amd64
   mv frp-tun_v0.5.2_amd64 /usr/local/bin/frp-tun
   ```
4. Start the service and inspect runtime status:
   ```bash
   systemctl start frp-tun
   ```

---

## Rollback

If unexpected behavior occurs post-upgrade:
1. Stop the service: `systemctl stop frp-tun`;
2. Restore the previous verified binary to `/usr/local/bin/frp-tun`;
3. Clean up residual policy routes and interfaces (if any): `ip link delete frp-tun:0 2>/dev/null || true`;
4. Restart the previous daemon version.
