## 摘要

- 修复 `p2p.mtu_adjust` 观察器的会话切换语义：会话或路径切换后，稳定观察窗口与同值建议去重均会重置；`auto` 模式的 30 分钟动作冷却跨会话保留，杜绝基于未观察到的新路径触发自动 MTU 变更。
- 文档补充真机 A/B 测试的 CPU 测量口径注记：A/B 两侧分别运行用户态与内核态 WireGuard 后端，CPU 数据来自进程 rusage 口径，两端数值不可横向比较。

## 已验证范围

- 五种架构的发行二进制均已与 `checksums.txt` 比对通过。
- 动态 MTU 的 `suggest` 与 `auto` 模式已在两台 MT7981B 设备的真机验证中确认通过；详细测量数据待入库后披露。
- CPU 测量口径注记：[v0.5.7](/releases/v0.5.7/) 报告的真机 A/B 测试中，接收侧与发送侧的 CPU 增量分别来自不同的 WireGuard 后端——一端为用户态实现，WireGuard 加解密计入进程 CPU；另一端为内核态实现，不含该部分。两者均为进程 rusage 口径，两端数值不可横向比较，各自仅用于与自身 A/B 基线对比。

## 已知限制

- 硬件、网络路径和负载不同，MTU 建议、分片情况及 CPU 收益可能不同；请在目标环境验证。
- 交叉编译资产不构成特定硬件、持续高负载、非零 `SO_MARK` 或复杂 NAT 场景的兼容性保证。
- 软件不提供自动更新或可用性 SLA；请参阅 [EULA](https://github.com/elkpi/frp-tun-page/blob/main/EULA.md)。

## 升级

在维护窗口备份现有配置和旧版二进制，确认独立的回退路径。下载匹配架构的二进制并核对摘要后，停止服务、替换二进制并重启，然后运行 `frp-tun doctor` 检查状态。已有启用 journal 时，重启恢复已提交配置；需要更改配置时使用 `frp-tun apply`。详见[升级与回退](/operations/upgrade-rollback/)。

## 回退

停止服务，恢复备份的旧版二进制，再启动并检查状态。配置回退和二进制回退并非同一操作；操作前请核对目标旧版的发行说明及其 journal 行为。

## 撤回

如发现重大安全或稳定性问题，维护者将在公开 Release 页面标记撤回，并按 [SECURITY.md](https://github.com/elkpi/frp-tun-page/blob/main/SECURITY.md) 发布通告。
