## 摘要

`frp-tun v0.5.3` 重点实现自研 native QUIC P2P 直连链路的端到端对等发起（建联方向对称化），彻底解决单向固定发起导致的不可逆 NAT 穿透失败；同时修复端口块（CGNAT）打洞成功端点被新鲜度门槛误杀卡在中继的缺陷。

### 主要改进特性

1. **端口块 NAT 新鲜度误杀修复**：针对对端处于 CGNAT 端口块环境，放行已通过 QUIC 双向加密认证的同一对端 IP 映射端点，丢弃日志精确打印失败原因，彻底解决打洞命中后仍卡死在 relay 的缺陷；
2. **自研 QUIC 直连建联方向对称化（Peer 对等）**：引入动态单发起方状态机，默认由站点角色决定起始发起方（visitor 发起、proxy 接受），连续 3 次终结性失败自动翻转建联方向，翻转事件立即触发首拨重试；配置 2 分钟迟滞防抖，网络拓扑变化与改号时自动重置回默认方向；
3. **双端常驻 QUIC 监听与冲突收敛**：visitor 与 proxy 角色均在 loopback UDP 套接字上常驻监听，任一端可作为 acceptor 接受入站。双 dialer 同时拨号时由 `openDialerSession` 收集候选，基于全局 SiteID 字典序（大者胜出）确定性保留一条连接，无副作用关闭败者；
4. **流握手首帧防死锁**：重构 `authenticateWithOrder`，由建联方向（而不是站点角色）决定 TLS/认证首写顺序，消除 dialer 空流不发 STREAM 帧导致 acceptor `AcceptStream` 永久阻塞的死锁缺陷；
5. **全链路 `DialRole` 可观测性**：`carrier.Session` 与 `supervisor.Status`（顶层及 `Peers[]`）透出 `DialRole`（`"dialer" / "acceptor"`），会话建立日志行输出 `, dial=` 标记；
6. **严格向后兼容与平稳回退**：wire 协议保持严格 canonical 编码兼容；中继路径（STCP/XTCP 经 frps）完整保留原有 visitor/proxy 语义及私有中继 Preferred Hub 优选逻辑。

## 升级

1. 备份当前网关上的配置文件（如 `/etc/frp-tun/config.toml`）；
2. 停止当前守护进程：
   ```bash
   systemctl stop frp-tun
   ```
3. 替换二进制并赋予执行权限：
   ```bash
   chmod +x frp-tun_v0.5.3_amd64
   mv frp-tun_v0.5.3_amd64 /usr/local/bin/frp-tun
   ```
4. 启动服务并检查状态：
   ```bash
   systemctl start frp-tun
   ```

---

## 回退

若在升级后发现网络异常或打洞受阻：
1. 停止服务：`systemctl stop frp-tun`；
2. 将备份的历史版本二进制恢复至 `/usr/local/bin/frp-tun`；
3. 清理残存策略路由与接口（如有）：`ip link delete frp-tun:0 2>/dev/null || true`；
4. 重新启动历史版本守护进程。

## 撤回

若发现重大安全漏洞或内核奔溃缺陷，项目维护者将在 Release 页面标明 `REVOKED — DO NOT USE`，下架对应二进制资产，并通过 [SECURITY.md](https://github.com/elkpi/frp-tun-page/blob/main/SECURITY.md) 发布安全修复通告。
