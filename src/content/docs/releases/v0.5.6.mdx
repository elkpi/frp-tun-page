## 摘要

`frp-tun v0.5.6` 修复崩溃或重启后未恢复已提交配置，以及 `apply` 失败后不能回到上一代的问题。已有启用记录时，`run` 恢复 journal 中的配置，而不是磁盘上后来改过的配置文件。`apply` 在隔离、转发、运行时或 journal 提交失败时回滚到上一代，并先恢复隔离再重建运行时。不完整、损坏或摘要不符的 journal 会拒绝启动。

### 主要变更

1. **重启恢复已提交配置**：状态目录中的 `journal.json`（默认 `/etc/frp-tun/journal.json`）记录服务应启用且配置摘要一致时，`run` 使用其中的配置调用恢复。配置文件缺失、无法解析，或与 journal 不一致时，启动仍使用 journal，并在错误输出写入 `config file ignored`。journal 文件不存在时，才按配置文件全新激活；
2. **拒绝不可校验的 journal**：空对象、损坏的 JSON、启用状态不一致、缺少可校验配置，或配置摘要不符时，`run` 以退出码 4 拒绝启动，不会退回配置文件；
3. **`apply` 失败回滚到上一代**：已有上一代配置时，隔离、转发、增量对端、运行时或 journal 写入失败会在 30 秒预算内先恢复上一代隔离，再重建上一代运行时，并把原始错误返回给客户端。journal 只在整次 `apply` 成功后更新，已记录的退役 IPv6 前缀会保留。校验失败，或试图在 `apply` 中修改站点 ID，会在改动系统之前拒绝；
4. **回滚失败后禁止继续 apply**：回滚本身失败或超过 30 秒时，服务标记为未激活，已提交的 journal 保持不变。此后 `apply` 失败并包含 `restart required`，需要重启进程后才能再次 `apply`；
5. **断开连接会取消 apply，回滚预算独立**：控制套接字对 `apply` 的截止时间为 90 秒，操作本身限 60 秒，以便回滚结果仍能写回。客户端断开会取消这次 `apply` 请求；回滚使用独立的 30 秒预算，不跟随该取消。`down` 的套接字截止时间仍为 60 秒。

## 已知限制

- `frp-tun down` 会清理本实例网络资源，并写入 `desired_enabled=false` 的 journal，但该记录不含 `site_id`。`v0.5.6` 的 `run` 把这种记录视为不完整停用状态，拒绝启动并报告 `journal missing explicit stopped state`。成功执行 `down` 且确认网络资源已清理之后，删除状态目录中的 `journal.json`（默认 `/etc/frp-tun/journal.json`），下一次 `run` 才会按配置文件全新激活。服务仍应保持已提交配置时，不要删除该文件；
- 本版本发布的自动化交叉编译资产不构成特定商业硬件平台的兼容性背书；
- 物理设备高压负载、特定硬件下的非零 `SO_MARK` 特权行为与跨复杂多层 NAT 的穿透效果仍需在实际网络环境中验证；
- 遵循 [EULA 免责声明](https://github.com/elkpi/frp-tun-page/blob/main/EULA.md)，不提供在线自动静默更新与可用性 SLA 保证。

## 升级

1. 备份当前网关上的配置文件（如 `/etc/frp-tun/config.toml` 或 `/etc/config/frp-tun`）。已有启用 journal 时，替换二进制后重启恢复的是 journal 里的配置，不是后来改过的配置文件；
2. 停止当前守护进程：
   ```bash
   systemctl stop frp-tun
   ```
3. 替换二进制并赋予执行权限：
   ```bash
   chmod +x frp-tun_v0.5.6_amd64
   mv frp-tun_v0.5.6_amd64 /usr/local/bin/frp-tun
   ```
4. 启动服务。需要改配置时使用 `frp-tun apply`，不要只改文件再重启：
   ```bash
   systemctl start frp-tun
   frp-tun apply -c /etc/frp-tun/config.toml
   ```
5. 查看运行状态：
   ```bash
   frp-tun doctor
   ```

## 回退

这里的回退是换回上一版二进制，不是 `apply` 失败时守护进程自动回到上一代配置。

1. 停止服务：`systemctl stop frp-tun`；
2. 将备份的历史版本二进制恢复至 `/usr/local/bin/frp-tun`；
3. 若需要放弃 `v0.5.6` 已提交的配置，先在本版本执行 `frp-tun down`。若下一次启动被 `journal missing explicit stopped state` 拒绝，确认网络资源已清理后删除 `journal.json`，再启动历史版本；
4. 重新启动历史版本守护进程。
