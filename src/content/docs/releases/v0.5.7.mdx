## 摘要

- 新增按需 `frp-tun perf` 采样，按对端输出区间吞吐、CPU、RSS、探针 RTT、jitter、丢包、分片和帧计数、已确认的 datagram 载荷上限等。`doctor` 修正转发、防火墙等诊断口径；`status` 透出观测错误、流量计数器代际和 datagram 可用性。
- QUIC datagram 发送上限不再固定为 1200，而是探测路径限制，在路径变化或 `DatagramTooLargeError` 时收敛。新增 `p2p.mtu_adjust` 策略：`suggest`（默认）、`auto`、`off`。MTU 建议考虑 WireGuard 填充和封装开销。
- 改进空网络 journal 时自有规则、路由和接口直连路由的恢复；修复 `apply` 半关闭误取消、运行时上下文生命周期和已取消操作提交等问题；网关端口映射支持退避重试。

## 已验证范围

- 五种架构的发行二进制均已与 `checksums.txt` 比对通过。
- 上游报告的 OpenWrt MT7981B 真机 A/B 测试中，单向吞吐约 1.1 Mbps；MTU 为 1360、路径确认载荷上限为 1396 时，`tx_frag`、`fragment_frames` 和 `reassembled` 均为零，接收侧 CPU 增量下降约 29%，发送侧下降约 15%。发送侧剩余主要开销为 QUIC 逐包加密和帧封装。这是特定设备和测试条件下的结果。
- 上游报告包含跨进程崩溃恢复、失败 `apply` 等回归测试。

## 已知限制

- 硬件、网络路径和负载不同，MTU 建议、分片情况及 CPU 收益可能不同；请在目标环境验证。
- 交叉编译资产不构成特定硬件、持续高负载、非零 `SO_MARK` 或复杂 NAT 场景的兼容性保证。
- 软件不提供自动更新或可用性 SLA；请参阅 [EULA](https://github.com/elkpi/frp-tun-page/blob/main/EULA.md)。

## 升级

在维护窗口备份现有配置和旧版二进制，确认独立的回退路径。下载匹配架构的二进制并核对摘要后，停止服务、替换二进制并重启，然后运行 `frp-tun doctor` 检查状态。已有启用 journal 时，重启恢复已提交配置；需要更改配置时使用 `frp-tun apply`。详见[升级与回退](/operations/upgrade-rollback/)。

## 回退

停止服务，恢复备份的旧版二进制，再启动并检查状态。配置回退和二进制回退并非同一操作；操作前请核对目标旧版的发行说明及其 journal 行为。

## 撤回

如发现重大安全或稳定性问题，维护者将在公开 Release 页面标记撤回，并按 [SECURITY.md](https://github.com/elkpi/frp-tun-page/blob/main/SECURITY.md) 发布通告。
