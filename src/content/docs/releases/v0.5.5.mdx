## 摘要

`frp-tun v0.5.5` 是一个面向生产运行深度收敛、TCP 传输稳定性强化、诊断体系升级与生态拓展的里程碑正式版本。本版本全面完成了控制面信令收敛与日志分级、引入出站隧道 TCP MSS Clamping 杜绝大包黑洞、将 `doctor` 升级为在线/离线双模全景诊断引擎、在数据面消除环回 UDP 读取系统调用开销，并正式发布了 OpenWrt UCI 配置规范与 `luci-app-frp-tun` 实时监控面板。

### 主要改进特性

1. **控制面信令收敛（Signaling Convergence）**：在 `peerExchange` 对等协商中引入 10 秒最小发送间隔与指纹去重（Fingerprint Deduplication）。本地或对端候选代次（Generation）递增及候选集合发生真实拓扑变更时立即放行广播，彻底杜绝稳态下毫秒级重复广播风暴；
2. **日志语义分级与降噪**：将常规稳态下的通道 TTL 周期性续期输出由高频刷新改为周期聚合输出，消除 77.4% 的刷屏日志噪声；真实集合增删与故障变更仍保持 `Info` 审计级别；
3. **会话槽位全状态诊断**：当触发 `candidate_open_slot_full` 异常时输出结构化槽位快照 `[family:state:id:age]`，并增加 10 秒限频保护，便于精确定位僵尸会话或握手挂起对端；
4. **出站隧道自动 TCP MSS Clamping**：在 `nftables` 转发链中针对出站隧道报文自动双向注入 MSS 钳制（`tcp flags syn tcp option maxseg size set rt mtu - 40`），从内核转发层彻底解决隧道 Overlay 封装导致的跨站大包分片丢包与 HTTPS 假死黑洞；
5. **Doctor 双模全景诊断体系**：升级 `doctor` 命令为“在线全景探测 + 离线静态环境预检”双模架构。运行中实例通过控制套接字读取 IPC 实时链路状态、RTT、丢包率、活动/备用链路状态；离线模式自动预检 TUN 设备、凭证配置与 OpenWrt fw4 `mtu_fix` 合规性；
6. **环回数据面性能压榨**：消除 WireGuard 环回（Loopback）UDP 读操作上的逐包 `SetReadDeadline` 系统调用，消除额外内核陷入与内存开销；实测单包 CPU 消耗下降 13.4%，吞吐提升 16.1%，p50 时延下降 74.2%，保持零内存膨胀；
7. **OpenWrt 生态全栈拓展**：官方提供 `/etc/config/frp-tun` UCI 配置模板、Procd 双模启动合成（支持独立 TOML 模式与 UCI 动态渲染模式）以及 `luci-app-frp-tun` 实时状态面板。

## 升级

1. 备份当前网关上的配置文件（如 `/etc/frp-tun/config.toml` 或 `/etc/config/frp-tun`）；
2. 停止当前守护进程：
   ```bash
   systemctl stop frp-tun
   ```
3. 替换二进制并赋予执行权限：
   ```bash
   chmod +x frp-tun_v0.5.5_amd64
   mv frp-tun_v0.5.5_amd64 /usr/local/bin/frp-tun
   ```
4. 运行双模环境预检并启动服务：
   ```bash
   frp-tun doctor -c /etc/frp-tun/config.toml
   systemctl start frp-tun
   ```
5. 查看在线运行状态：
   ```bash
   frp-tun doctor
   ```

---

## 回退

若在升级后发现网络异常或打洞受阻：
1. 停止服务：`systemctl stop frp-tun`；
2. 将备份的历史版本二进制恢复至 `/usr/local/bin/frp-tun`；
3. 清理残存策略路由与接口（如有）：`ip link delete frp-tun:0 2>/dev/null || true`；
4. 重新启动历史版本守护进程。

## 撤回

若发现重大安全漏洞或内核崩溃缺陷，项目维护者将在 Release 页面标明 `REVOKED — DO NOT USE`，下架对应二进制资产，并通过 [SECURITY.md](https://github.com/elkpi/frp-tun-page/blob/main/SECURITY.md) 发布安全修复通告。
