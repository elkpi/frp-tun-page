## 摘要

`frp-tun v0.5.4` 是一个关键的稳定性和恢复机制增强版本。本版本彻底解决了在无外部 STUN 候选或本地未发现直连候选端点时，节点可能陷入高频空候选恢复通知与重复准备的忙循环（Recovery Event Storm）缺陷，引入基于网络纪元（Network Epoch）的退避锁定，并大幅净化运行日志。

### 主要改进特性

1. **空候选恢复循环与事件风暴抑制**：优化 `refreshLocalUpdate` 恢复事件触发判定，仅在协议族的准备状态（`Prepared`）发生真实翻转或生成新一代有效候选集时才向 supervisor 广播 `signalRecovery`，彻底消除由于无候选导致的无限连续恢复调用；
2. **网络纪元（Network Epoch）退避重试防护**：在 `prepareFamilyLoop` 中对无有效候选（`errNoLocalCandidates`）场景增加纪元一致性校验。在退避等待期间，若本地网络拓扑/纪元未发生变化，即使收到重复触发请求也不打断退避定时器，只有在网络真实变动或定时器超时后才发起重试，防止突发重试击穿退避；
3. **准备日志降噪与审计优化**：将空候选阶段性未就绪从严重错误日志中剥离，避免无候选正常退避期间刷屏污染运行日志；
4. **测试覆盖与边界收敛**：补充 `empty_candidate_recovery_test.go` 针对 peering engine 与 supervisor 的端到端测试，覆盖无 STUN 候选、负缓存过期及突发并发请求等严苛场景。

## 升级

1. 备份当前网关上的配置文件（如 `/etc/frp-tun/config.toml`）；
2. 停止当前守护进程：
   ```bash
   systemctl stop frp-tun
   ```
3. 替换二进制并赋予执行权限：
   ```bash
   chmod +x frp-tun_v0.5.4_amd64
   mv frp-tun_v0.5.4_amd64 /usr/local/bin/frp-tun
   ```
4. 启动服务并检查状态：
   ```bash
   systemctl start frp-tun
   ```

---

## 回退

若在升级后发现网络异常或打洞受阻：
1. 停止服务：`systemctl stop frp-tun`；
2. 将备份的历史版本二进制恢复至 `/usr/local/bin/frp-tun`；
3. 清理残存策略路由与接口（如有）：`ip link delete frp-tun:0 2>/dev/null || true`；
4. 重新启动历史版本守护进程。

## 撤回

若发现重大安全漏洞或内核奔溃缺陷，项目维护者将在 Release 页面标明 `REVOKED — DO NOT USE`，下架对应二进制资产，并通过 [SECURITY.md](https://github.com/elkpi/frp-tun-page/blob/main/SECURITY.md) 发布安全修复通告。
