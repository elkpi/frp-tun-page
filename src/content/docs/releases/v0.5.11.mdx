## 摘要

- **LoopbackBind 批量收发**：使用 IPv4 `ReadBatch`/`WriteBatch`，批量上限为 16 包；系统不支持批量 API 时永久回退到单包 IO。超过上限的批次分块完整发送；每次调用使用独立消息数组，隔离多个 peer 的并发收发。
- **Endpoint 入站攒批**：非阻塞排空最多 16 帧后立即 flush，不增加固定等待；遇到控制帧时，优先 flush 已攒的数据帧。
- **reassembler 惰性过期**：分片重组器的 `expire` 清理在未到期时不遍历分片状态；到期后再执行清理。
- **取消与 deadline 对齐**：`WriteBatch` 检查 context 取消；`TryReadFrame` 遵守已过期的读取 deadline。
- **公平基准结果**：同一基准夹具、同批量 MemoryTUN，仅 Bind 实现不同；1000 pps 每档 5 个样本均闭合且零丢包。Δ% 正值表示改善（after 相对 before）。CPU：64B +2.7%、512B -2.0% 均在噪声范围；1400B 档 CPU 降低 22.9%，是唯一超过 10% 门槛的档位。常规 1k pps 网关负载仅大包档有实证 CPU 收益。
- **Heap 结果与修正**：每包增加 3.1 个对象（约劣化 57%），来自 `x/net` `ReadBatch` 为每包构造 `UDPAddr`；本仓侧的消息数组、Buffers 与地址复用已做到零分配。首版报告的 heap -9.2%~-10.1% 收益因夹具差异作废，不应引用。
- [v0.5.10](/releases/v0.5.10/) 及更早版本已验证的能力和结论继续有效。

## 已验证范围

- 官方五架构发行二进制均已与随附的 `checksums.txt` 比对通过。
- 公平基准使用相同夹具和批量 MemoryTUN，仅被测 Bind 实现不同；1000 pps 的 64B、512B、1400B 各 5 个样本全部闭合、零丢包。
- CPU 变化：64B +2.7%、512B -2.0% 均在噪声范围；1400B 档 CPU 降低 22.9%，超过 10% 门槛。故仅能声称常规 1k pps 网关负载的大包档有实证 CPU 收益。
- Heap 每包增加 3.1 个对象（约劣化 57%），为 `x/net` `ReadBatch` 构造 `UDPAddr` 的库内开销；本仓侧复用已为零分配。首版报告的 heap -9.2%~-10.1% 收益由于夹具差异作废。
- 64MB/16MB 内存设备仍为压力评估档，非支持声明。

## 已知限制

- 基准结果和实际收益受硬件、网络路径与负载影响；CPU 证据不支持把单一大包档收益泛化到所有负载。
- `x/net` `ReadBatch` 引入每包 `UDPAddr` 分配，导致 heap 对象数增加；首版 heap 收益数字已作废。
- 64MB/16MB 内存设备仍为压力评估档，非支持声明。
- 交叉编译资产不构成特定硬件、持续高负载、非零 `SO_MARK` 或复杂 NAT 场景的兼容性保证。
- 软件不提供自动更新或可用性 SLA；请参阅 [EULA](https://github.com/elkpi/frp-tun-page/blob/main/EULA.md)。

## 升级

在维护窗口备份现有配置和旧版二进制，确认独立回退路径。下载匹配架构的二进制并核对摘要后，停止服务、替换二进制并重启，然后运行 `frp-tun doctor` 检查状态。已有启用 journal 时，重启恢复已提交配置；需要更改配置时使用 `frp-tun apply`。详见[升级与回退](/operations/upgrade-rollback/)。

## 回退

停止服务，恢复备份的旧版二进制，再启动并检查状态。配置回退和二进制回退并非同一操作；操作前请核对目标旧版的发行说明及其 journal 行为。

## 撤回

如发现重大安全或稳定性问题，维护者将在公开 Release 页面标记撤回，并按 [SECURITY.md](https://github.com/elkpi/frp-tun-page/blob/main/SECURITY.md) 发布通告。
