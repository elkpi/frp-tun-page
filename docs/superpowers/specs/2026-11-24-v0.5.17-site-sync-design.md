# v0.5.17 官网同步设计

## 意图

上游 `elkpi/frp-tun` 已发布 v0.5.17（tag 提交 `9b4541af8c55776d3f910a49c0d1b296b231086c`），新增双端隧道 MTU 协商与直连监听端口范围漂移。本站需要同步中英发行说明、示例配置、字段字典与 `status` 新字段，使官网口径与上游 Release / `docs/operations.md` / `docs/compatibility.md` 一致，并在对外发布前完成本地构建与契约校验。

## 目标

- 中英新建 `releases/v0.5.17.mdx`，slug 显式声明为 `releases/v0.5.17` / `en/releases/v0.5.17`，使用已核验的上游资产摘要与官网 Release 下载链接。
- 发行说明覆盖：两端 v0.5.17 时的 MTU 协商、只降不升、5 分钟冷却、默认 1420、同配置 `site.mtu == peer.mtu` 但两机可不同；`p2p.listen_port_range` 的触发/限频/互斥/防火墙与 journal 语义；`p2p.mtu_adjust` 与协商的优先级；`status` 五个新字段和端口语义。
- 中英 `full-reference` 新增 `p2p.listen_port_range` 与协商优先说明，更新 `mtu` 与 `mtu_adjust` 注释；`minimal-two-site` 展示两端不同 MTU（1420 / 1360）及可选漂移范围。
- 中英 `cli-reference` 的 `status` 段增加 `effective_mtu`、`mtu_source`、`mtu_advertise`、`suggested_mtu`、`listen_port_drifts_24h`、Peers[].ListenPort 与 Supervisor.LocalEndpoint 语义；`listen_port_drifts_24h` 明确只是计数。
- 全站“当前版本”指针从 v0.5.16 切到 v0.5.17（首页、releases 索引、OpenWrt、full-reference 字段字典说明），契约测试同步更新。
- `npm test`、`npm run check`、`npm run build`（含 prebuild 校验）全绿。

## 非目标 / 反目标

- 不把“创建官网 GitHub Release、上传五架构资产、触发 Pages 部署”自动纳入本地文档提交；这些对外动作须在测试通过后单独取得用户明确批准。
- 不宣称真机端口封禁、非零 `SO_MARK`、OpenWrt 硬件已验证，不宣称性能收益或更低资源占用。
- 不修改闭源核心仓库，不复制上游内部规格全文；公开内容仅采用已发布的 Release 口径与已核验的摘要。

## 约束

- 公开内容遵守 `scripts/validate-public-content.mjs` 的主机名/IP/密钥白名单，MTU 示例网段仍用 RFC 5737 地址，凭据全用 `REPLACE_WITH_*`。
- 版本化发行说明必须显式写 `slug`（Astro github-slugger 会吞掉点号）；validate-release-metadata 要求规定章节与 version/slug 匹配。
- Starlight 要求每个中文页面有英文对应页；契约测试逐项锁定新版本关键事实与验证边界。
- 官网下载 URL 沿用 `elkpi/frp-tun-page` Release 约定；摘要以刚从上游下载、通过 `sha256sum -c` 的 `checksums.txt` 为准，并与 GitHub API digest 一致。
- commit 粒度：release notes + 契约测试一笔，站点/配置/CLI 同步一笔；设计与计划文档可并入后一笔或单独一笔，避免与功能文案混杂。

## 方案选择

1. **沿用 v0.5.16 的两提交模式（推荐）**：第一笔新增中英发行说明与契约测试（含 6 个摘要断言）；第二笔更新版本指针、示例、字段字典、CLI 与契约测试。历史一致、cherry-pick 与回滚清晰。
2. 单笔大提交：省事但把发布说明与站点同步混在一起，不符合全局 commit 粒度偏好。
3. 只改版本指针：无法满足 `/releases/v0.5.17/` 可访问、示例配置与字段说明同步的要求。

选择方案 1。

## 实现要点（已定部分）

- 发行说明摘要按上游 Release 写，验证边界按上游“CI + 原版 frps v0.71.0 环回通过；真机端口封禁、非零 SO_MARK、OpenWrt 未验证”写，不新增未证实结论。
- 下载表使用 `frp-tun_v0.5.17_<arch>` 与 `checksums.txt` 六个官网 Release URL；摘要块写入五个二进制值，`checksums.txt` 自身摘要写入“已验证范围”。
- 示例配置：`minimal-two-site` 保留原最小双站点段，新增场景 C：站点 A `mtu = 1420`、站点 B `mtu = 1360`（同一配置内 site/peer mtu 相等），可选 `listen_port_range = "53000-53999"`，并说明旧端口保留 120 秒、稳定连接不漂移。
- `full-reference` 的 `[site]` / `[peer]` 模板注释改为“同一配置内两值必须相等；两台机器可不同，协商后取较小者”；`[p2p]` 模板新增 `# listen_port_range = "53000-53999"` 并写清缺省空、触发与限制、范围冲突与 `manage_firewall` 一次放行；`mtu_adjust` 补充“对端支持协商时协商优先，off 只关单边调整”。
- `cli-reference` 的 `status` 输出说明追加五个新字段，并明确 `Peers[].ListenPort` / `Supervisor.LocalEndpoint` 为活动会话实际端口、无活动会话时 ListenPort 回退配置值。`listen_port_drifts_24h` 是 24h 内成功漂移次数（非开关、未启用时为 0）。
- 契约测试：新增 v0.5.17 notes 测试（版本/frontmatter/摘要/摘要值/验证边界）、版本指针测试推进到 v0.5.17、新增配置与 status 字段文档断言；保留并运行既有全部测试。

## 留给实现者的部分

- 具体文案逐句对照上游 Release 与 `docs/operations.md` §7；如上游表述与用户给定口径有细微差异，以用户口径为准，不扩大结论。
- 校验失败时按 `scripts/validate-*` 与契约测试报错修正，不绕过门禁。
- 对外发布审批范围单独请求，不因文档构建通过而自行创建 Release 或部署 Pages。
