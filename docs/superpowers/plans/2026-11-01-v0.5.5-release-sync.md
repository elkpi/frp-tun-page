> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Synchronize the core daemon v0.5.5 release to the public documentation site (`frp-tun-page`), publish dual-locale release notes, update version references, CLI, troubleshooting, architecture, and OpenWrt documentation, generate release publication helper script, publish GitHub Release `v0.5.5` on `elkpi/frp-tun-page`, and verify test and build integrity.

**Architecture:** Add dual-locale release documentation (`releases/v0.5.5.mdx` and `en/releases/v0.5.5.mdx`), update site navigation/indices, landing page, CLI reference (`doctor` dual-mode online/offline and QoS probing), troubleshooting (`candidate_open_slot_full` slot snapshot & MSS clamping), architecture (control-plane signaling convergence & loopback performance), and OpenWrt documentation (UCI template, Procd synthesis, and fw4 mtu_fix). Add publication helper script `scripts/publish-release-v0.5.5.sh`. Verify all contract tests and security validators.

**Tech Stack:** Astro 5, Starlight, Node.js native test runner (`node --test`), Markdown/MDX, Shell/Bash (`gh release`).

**Spec:** Core daemon release `v0.5.5` (commit `9d51c57`, upstream release `https://github.com/elkpi/frp-tun/releases/tag/v0.5.5`, PR #22).

## Global Constraints

- Frontmatter slug must explicitly include the version dot notation: `slug: releases/v0.5.5` (ZH) and `slug: en/releases/v0.5.5` (EN) to prevent Astro dot stripping.
- Release notes require exact mandatory sections: `摘要`, `已验证范围`, `已知限制`, `升级`, `回退`, `验证`, `撤回` (and EN equivalents: `Summary`, `Verified Scope`, `Known Limitations`, `Upgrade`, `Rollback`, `Verification`, `Revocation`).
- Strictly prohibit forbidden platform claims (`OpenWrt 已支持` or `非零 SO_MARK 已验证`).
- Strictly enforce RFC 5737 (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`) and RFC 3849 (`2001:db8::/32`) IP addresses, and placeholder credentials (`REPLACE_WITH_*`). No RFC 1918 private IPs (e.g. `192.168.x.x`, `172.16-31.x.x`).
- All documentation in `src/content/docs/` must maintain 1:1 English parity in `src/content/docs/en/` enforced by `tests/documentation-contract.test.mjs`.
- Maintain fine-grained git commits for cherry-pick readiness per global user preferences.

## Review Focus

1. Missing dot in release note slugs causing route collisions or 404s (`missing-or-mismatched-slug`).
2. Accidental inclusion of RFC 1918 private IPs (e.g. `192.168.10.0/24` or `172.31.255.1/32` in OpenWrt UCI configuration examples) tripping `validate-public-content.mjs`.
3. Discrepancy between published binary SHA256 hashes and the release notes checksum table.
4. Missing English parity in `tests/documentation-contract.test.mjs` breaking CI.
5. Unhandled doctor options or command signatures diverging between CLI reference and core daemon.
