# v0.5.16 官网同步 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为官网新增 v0.5.16 中英发行说明、更新版本指针并补齐 auto 数据面相关文档，使全站对外口径与上游 Release 一致且校验门禁全绿。

**Architecture:** 沿用 v0.5.15 的两提交发布模式：Task 1 新增发行说明与契约测试，Task 2 更新全站版本指针与既有文档；两个任务各自有可独立验证的测试周期。内容全部静态 MDX，无需新增依赖或后端。

**Tech Stack:** Astro 5 + Starlight MDX，Node 原生 `node --test`，`scripts/validate-public-content.mjs` 与 `scripts/validate-release-metadata.mjs`。

**Spec:** `docs/superpowers/specs/2026-11-22-v0.5.16-site-sync-design.md`

## Global Constraints

- 新发行说明 slug 必须是 `releases/v0.5.16` / `en/releases/v0.5.16`；frontmatter 必须包含 `version: v0.5.16`、`status: release`、`published: true`。
- 公开内容必须通过 `npm run validate:content`：主机名/IP/密钥白名单、RFC 5737 示例网段、`REPLACE_WITH_*` 占位符。
- 文案不得宣称性能收益、非零 `SO_MARK` 支持或 OpenWrt 真机验证；必须保留“本地环回 E2E 通过、`-race` 由 CI 验证”的边界。
- 上游 post-tag 提交 `41287da` 仅修改 `internal/plane/review_regression_test.go`（双 Hub 切回回归测试），归入 v0.5.16 功能范围；在发行说明“已验证范围”补记该修复，不新建版本条目、不重发资产。
- 场景样例落在既有 `configuration/minimal-two-site.mdx`（中英）页面，不新增侧边栏导航项；auto 场景使用 RFC 5737 示例网段与 `REPLACE_WITH_*` 占位符。
- 升级提示必须写明：`sync_port` 缺省由固定 51830 改为按站点对派生；与固定模式或旧版本互通时两端显式配置同一可用端口。
- 每个任务结束即提交；提交信息遵循仓库历史：`docs(releases): ...` 与 `docs(site): ...`。

## Review Focus

- `checksums.txt` 与五个二进制的 SHA256 是否与上游 Release 完全一致 → Task 1 契约测试断言 6 个摘要。
- `sync_port` 默认值变更是否明确写成“两端显式配置同一可用端口” → Task 1 中英发行说明测试断言该句式；Task 2 配置字典测试断言说明存在。
- 验证边界是否被误写成“真机/性能收益已验证” → Task 1 契约测试断言中英“不宣称性能收益/未验证 SO_MARK 与 OpenWrt”的否定句。
- 中英版本指针是否遗漏或混用 v0.5.15 → Task 2 契约测试断言 8 处指针 + releases 索引“当前稳定版本”唯一性。
- `frp-tun pin` 与 `auto` 数据面是否在中英文档中同步出现 → Task 2 契约测试断言两语言 cli-reference 与 operations 关键段落。

- [ ] **Step 3: 写中英发行说明**

按 v0.5.15 的章节结构（正式发布版本信息、摘要、下载与二进制资产、验证、已验证范围、已知限制、升级、回退、撤回）写两篇 v0.5.16 MDX。摘要要覆盖：
- `auto` 数据面：每个对端在直连（QUIC）、按配置顺序的私有 Hub、公共 STCP 间自动切换；连续 3 次无直连回落；直连稳定 60 秒且距上次回落 5 分钟后升回；更优先 Hub 恢复后立即切回；运行中不能热切换数据面。
- `hub_unencrypted`（缺省 false，仅 auto/tun-quic 生效）：两端都打开时私有 Hub 承载不套 WireGuard 的 IP，端到端认证/序号/重放窗口保留；公共 STCP 永远是 WireGuard。
- `frp-tun pin --peer <id> --target direct|relay|clear`：按对端钉住承载，跳过失败阈值与抑制期，仍需双方三次握手。
- 与固定 wg-quic 混合部署收敛到共享 STCP 中继；纯 Hub 节点不参与本站转发与路由。
- IPv6 动态前缀同步加固：签名快照序号、租期上限、到期撤销数据路由；`peer.ipv6.sync_port` 缺省按站点对派生，双 auto 通过签名信令交换实际端口。
- 升级提示：与固定模式或旧版本互通时两端显式配置同一可用端口（旧版默认 51830，新版按对派生）。
