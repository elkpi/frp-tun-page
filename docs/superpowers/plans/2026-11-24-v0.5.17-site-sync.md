# v0.5.17 官网同步 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为官网新增 v0.5.17 中英发行说明，更新示例配置、字段字典、`status` 字段与全站版本指针，使公开口径与上游 Release / 核心仓库 v0.5.17 一致且本地校验门禁全绿。

**Architecture:** 沿用 v0.5.16 的两提交模式：Task 1 新增发行说明与契约测试，Task 2 更新站点与既有文档；每笔提交独立可验证。内容全部是 Astro/Starlight 静态 MDX，不新增依赖或后端。创建官网 Release 与触发 Pages 部署不在此计划内。

**Tech Stack:** Astro 5 + Starlight MDX，Node 原生 `node --test`，`scripts/validate-public-content.mjs`、`scripts/validate-release-metadata.mjs`、`npm run check`、`npm run build`。

**Spec:** `docs/superpowers/specs/2026-11-24-v0.5.17-site-sync-design.md`

## Global Constraints

- 新发行说明 slug 必须是 `releases/v0.5.17` / `en/releases/v0.5.17`；frontmatter 包含 `version: v0.5.17`、`status: release`、`published: true`。
- 六个 SHA256 必须与已核验的上游资产一致：`be5593a269f2f0c5f722a4a8889e9589d8ec3910f3414063394edb54dd3fa82f`（checksums.txt）、`668d54744a99c3ab57cffb88784b68086dde6dc77441ad4101e0c5770b3b4562`（amd64）、`fc5cf79ba27640e2db8d66b6771bda0d7e1418402587d680267485405b1a949d`（arm）、`de7fdbe2043ea81710934c03f9054888dc79202ee030fb1d69adeed861c4bcc1`（arm64）、`5d094698833eee8f39b860c05977b9b97f7c7cc9f0883451c4a1f79289f6fc13`（mips）、`8252448531b2b23ec2b04f97d8d0e512dfba0531c49e6f2d6652d06eccfc8ce5`（mipsle）。
- 下载 URL 一律指向 `https://github.com/elkpi/frp-tun-page/releases/download/v0.5.17/<资产名>`；未获用户明确批准前不得创建该 Release 或上传资产。
- 公开内容必须通过 `npm run validate:content`：主机名/IP/密钥白名单、RFC 5737 示例网段、`REPLACE_WITH_*` 占位符。
- 发布说明不得宣称真机端口封禁、非零 `SO_MARK`、OpenWrt 硬件已验证，不得宣称性能收益或更低资源占用；验证边界限定为上游 CI 与原版 frps v0.71.0 环回。
- 同一配置中 `site.mtu` 必须等于 `peer.mtu`，两台机器可以不同；未配置默认 1420。协商值取两端通告与路径上限的较小者、只降不升、5 分钟冷却、热更新不断流；网络完全不通时无路径确认，不会自动降。
- `p2p.listen_port_range` 缺省为空且端口固定；仅在直连连续失败至少 3 次、持续至少 60 秒并再失败一次后漂移；间隔至少 30 分钟、24 小时最多 5 次、计数进 journal、portmapper 活跃禁用、旧端口保留 120 秒；不能与 `listen_port`、对端监听端口或 IPv6 `sync_port` 重叠。
- `p2p.mtu_adjust` 仍只有 `suggest`（默认）、`auto`、`off`；对端支持协商时协商优先；`off` 只关闭单边调整。
- `status` 新字段：`effective_mtu`、`mtu_source`（`negotiated` / `config`）、`mtu_advertise`、`suggested_mtu`、`listen_port_drifts_24h`；后者只是 24 小时内成功漂移次数，不是开关。`Peers[].ListenPort` 与 `Supervisor.LocalEndpoint` 是活动会话实际端口，无活动会话时 ListenPort 回退配置端口。
- commit 粒度：Task 1 与 Task 2 各一笔；提交信息沿用 `docs(releases): ...` 与 `docs(site): ...`。

## Review Focus

- 资产摘要写错或下载链接指向上游仓库 → Task 1 契约测试断言 6 个精确摘要和 `frp-tun-page/releases/download/v0.5.17/` 链接。
- 把协商写成“升也生效”、遗漏“网络完全不通不自动降”、或把 5 分钟冷却写成“立即生效” → Task 1 中英 notes 测试断言“只降不升 / lower only”“5 分钟 / 5 minutes”“网络完全不通 / no path confirmation”语句。
- 把端口漂移写成定时轮换、忽略 portmapper 或 24 小时上限 → Task 1 测试断言“稳定连接不漂移 / no drift while stable”“24 小时最多 5 次 / at most five times per 24 hours”“端口映射活跃时禁用 / portmapper active”；Task 2 配置测试断言 `listen_port_range = "53000-53999"` 及限制说明。
- 把 `listen_port_drifts_24h` 当作启用开关，或把 `Peers[].ListenPort` 误写成配置端口 → Task 2 CLI 测试断言“只是计数 / count only”和“活动会话实际端口 / actual port of the active session”“无活动会话回退 / falls back to configured port when no active session”。
- 中英页面缺页、slug 被 github-slugger 吞点、或验证边界被误写成真机通过 → Task 1 的 `expectedEnglishPages` 与 notes 测试、Task 2 全量 `npm test`、`npm run validate:releases` 与 `validate:content` 共同覆盖。
